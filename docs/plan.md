# 분당집 v2 리모델링 기록장

12월 리모델링을 앞두고 가족의 의견을 모으는 한 페이지 웹앱. Vercel 배포.
실제 비밀번호와 구성원 명단은 이 문서에 기재하지 않는다.

## 구현 범위

1. 공용 비밀번호로 로그인한 뒤 구성원을 선택한다.
2. 세 번째로 제공된 실측 평면도를 기준으로 2D 대시보드를 보여준다.
3. 공간에 마우스를 올리면 테두리를 강조하고, 클릭하면 그 위치에 의견을 작성한다. 평면도 내부 우상단의 ‘집 전체 의견 쓰기’ 버튼으로 위치 없는 의견도 남긴다.
4. 오른쪽 타임라인에서 의견을 최신순으로 보고 공간별로 필터링한다.
5. 기존 의견에 채택·기각 피드백을 남기면 해당 의견의 상태가 변경된다.

‘가족의 생각’ 옆 아이콘·이름 버튼을 누르면 가족별 카드가 펼쳐지고 구성원을 바꿀 수 있다. 가족별 성인 이모지와 이름만 표시한다. 별도 헤더 없이 프로젝트명과 일정을 평면도 제목에 합친다.
모바일 세로 화면은 평면도 다음에 의견 목록을 배치하고 페이지 전체를 스크롤한다. 도면 아래 ‘의견 쓰기’ 버튼으로 작성창에서 공간을 선택할 수 있다.

## 현재 모습과 To-be

현재 모습(As-is)과 리모델링 후(To-be)를 한 페이지 안에서 전환한다. 두 섹션 모두 2D/3D 전환을 제공하며, 현재 도면과 사진 기반 가구는 As-is에 속한다. To-be도 같은 벽·창문·미닫이문 구조를 2D·3D로 표시하며 가구만 비워둔다. 새 가구 배치와 의견 데이터는 아직 만들지 않는다. 기존 의견은 현재 모습에서 유지한다.

## 의견과 피드백

- 의견: 작성자, 공간 또는 집 전체, 도면 버전, 좌표(집 전체는 없음), 내용, 작성 시각.
- 상태: 검토 중 → 채택 또는 기각. 결정된 의견은 되돌리기만 표시하며, 기존 이력을 보존한 채 검토 중으로 돌린 뒤 새 피드백을 남긴다.
- 피드백: 작성자, 시각, 이전·이후 상태, 사유(선택).
- 원래 의견의 본문·작성자·위치를 유지하고 피드백 이력을 보존한다.
- 공간별 댓글 개수 버튼과 타임라인을 연결한다. 필터는 모든 의견, 집 전체, 개별 공간을 지원한다.
- 채택·검토 중·기각 표시를 각각 켜고 끈다. 기본은 모두 켜짐이며 공간 필터와 함께 적용한다. 평면도에서 특정 의견을 선택하거나 새 의견을 작성하면 해당 상태를 켜서 의견을 표시한다.
- 채택은 녹색, 기각은 빨간색으로 표시한다. 평면도에는 개별 번호 핀 없이 공간별 패널 하나에 채택(녹색)·검토 중(회색)·기각(빨강) 개수를 표시한다.
- 삭제 확인 후 의견을 목록과 집계에서 제외한다. 저장소에는 삭제 기록과 기존 피드백을 보존하며 동시 수정 충돌을 감지한다.
- 카드 공간 이름을 누르면 해당 영역을 잠깐 강조한다. 화면은 날짜만 표시하고 저장 타임스탬프는 유지한다.
- 개인별 승인 권한 없이 선택한 구성원으로 의견과 피드백을 기록한다.

## 평면도와 에셋

- [실측 평면도](../assets/floorplans/floorplan-measured.png): 2D 화면의 유일한 도면 기준. 벽·문·창문·치수와 공간 배치를 반영한다.
- 침실 1~4, 화장실 1~2, 발코니 1~3, 주방, 식당, 거실, 현관을 구분한다. 주방은 북쪽 조리 공간부터 보조 조리대 끝까지 직사각형으로 구분하고, 왼쪽 냉장고 구역과 그 아래는 식당으로 둔다. 공간 구분선에는 벽을 추가하지 않는다. 김치냉장고 북쪽에는 발코니 미닫이문을 반영한다. 원본의 21.19m²는 두 공간의 합계이므로 개별 면적은 표시하지 않는다.
- 도면 버전 `measured-v3`는 수정된 주방·식당 경계를 사용한다. 기존 버전의 의견·좌표·재시도는 원래 공간 기준을 보존한다.
- 이름과 별개로 공간 ID를 유지한다. 좌표는 도면 기준 비율로 저장한다. 기존 주방·식당 의견은 저장 좌표에 따라 주방 또는 식당으로 조회하며 작성자·본문·피드백 이력을 보존한다.
- [가구 이미지 1](../assets/floorplans/reference-3d/floorplan-top.png)과 [가구 이미지 2](../assets/floorplans/reference-3d/floorplan-perspective.png)는 향후 3D용 원본으로만 보관한다.
- 현재 대시보드에는 원본 가구 이미지와 NAVER 표시를 넣지 않는다. 새 실내 사진은 `assets/floorplans/reference-photos/`에 참고 원본으로 보관하고 화면에서는 직접 만든 가구 도형을 사용한다.

## 3D 초안

- 같은 화면에서 2D/3D로 전환한다. 실측 평면도의 공간·벽·개구부를 기준으로 회전·확대할 수 있는 모형을 만든다.
- 기본 벽 높이는 2m이며 전체 벽 2.4m로 전환할 수 있다. 위에서 보기, 시점 초기화, 공간 이름 표시를 지원한다.
- 벽 높이 2.4m, 문과 창문 높이는 임시값이다. 실내 사진을 참고해 식탁·의자 6개, 냉장고 2대, 세탁기, 김치냉장고, 싱크대·보조 조리대를 표현한다. 거실 사진에서는 TV·소파·컴퓨터 자리·스탠드 에어컨만 추가한다. 침실 4에는 침대·책상·책장·옷장만 사진 기준 추정 배치로 표시한다. 주방에서 발코니를 바라볼 때 TV는 오른쪽, 소파는 왼쪽이며 컴퓨터와 에어컨은 소파 옆 발코니 쪽에 둔다. 김치냉장고와 흰색 냉장고의 크기를 줄이고, 김치냉장고를 왼쪽에서 90도 회전해 배치한다. 모델상 약 67cm의 통로가 미닫이문과 이어지며 문은 왼쪽으로 열어둔다. 옆 여닫이문은 닫힌 상태로 표시한다. 이 간격은 실측이 아닌 추정값이다. 보조 조리대는 문 아래 벽선에 붙인다. 가구의 위치와 크기는 사진과 사용자 수정 기준이며 2D/3D가 같은 배치 데이터를 사용한다. 가구·가전 표시를 끌 수 있다.
- 미닫이문 5곳(두 냉장고 사이, 침실 2–발코니 2, 현관 실내 중문, 거실–발코니 3, 화장실 1)을 2D·3D 공통 데이터로 표현한다. 청록색 레일·프레임과 겹쳐 열린 문짝, 손잡이로 구분한다. 식당 북쪽과 화장실 1은 벽 바깥 레일에 문짝을 완전히 밀어두어 출입구를 비운다. 유리문은 푸른색, 화장실 문짝은 흰색이며 문짝 수와 개방 상태는 표시용 추정이다.
- 침실 2는 좌상단에서 서쪽 벽을 바라보는 긴 컴퓨터 책상, 우상단 모서리에 붙인 침대, 남쪽 수납 칸의 벽장을 표현한다. 발코니 2 오른쪽 끝에도 벽장을 둔다. 위치는 사용자 설명, 크기는 추정값이며 수납 칸 의견은 기존 침실 2 좌표에 연결한다.
- 침실 3은 남쪽 양옆 침대 2개, 왼쪽 벽을 따라 세로로 놓인 벽장(아래 침대와 같은 폭), 오른쪽 침대 북쪽 수납장과 동쪽 벽의 에어컨을 표현한다. 침실 4 침대는 베개가 남쪽을 향하고 북쪽에 수납장이 있다. 침실 2 컴퓨터 위에도 벽걸이 에어컨을 배치한다. 침실 3·4 수납장의 문은 북쪽으로 향한다. 벽걸이 제품은 바닥에서 띄운 높이로 표시한다. 거실 소파는 세 좌석이 같은 깊이인 일자형이다.
- 3D 공간 선택은 기존 도면 좌표로 변환하므로 2D와 의견·필터·강조 상태를 공유한다.
- 3D는 선택할 때만 불러온다. WebGL을 사용할 수 없는 브라우저는 2D로 이용한다.

## 저장과 인증

- Next.js App Router + Vercel Private Blob. 의견별 JSON 파일 하나로 저장한다.
- 현재 상태와 피드백 이력을 함께 조건부 갱신해 동시 변경 충돌을 감지한다.
- 고정된 요청 ID로 재시도 중복을 막는다. 운영과 미리보기의 저장 경로를 구분한다.
- 로컬 개발은 `.data/comments/`를 사용한다. Vercel에서는 로컬 파일을 영구 저장소로 사용하지 않는다.
- 공용 비밀번호와 구성원 정보는 서버 전용 환경변수로 관리한다.
- HttpOnly 세션 쿠키는 180일 유지한다. 로컬 스토리지는 구성원 선택과 로그인 유지 표시용이며 접근 권한은 서버가 확인한다.
- 의견과 구성원 API는 로그인 후 접근한다. 로그아웃과 비밀번호 변경에 따른 세션 무효화를 지원한다.

## 이번에 하지 않는 것

가구 이동·재질 편집, To-be 배치 작성, 정밀 시공용 3D, 사진 첨부, 일반 답글, 본문 수정, 투표, 알림, 개인별 계정.

## 공개 자료

- `/publications`에서 현재 상태로 초안을 만든다. As-is·To-be의 2D·3D를 고정 이미지로 저장하고 서버에서 채택된 의견의 공간·본문만 복사한다. 3D 스냅샷은 회전 가능한 모형이 아닌 이미지다.
- 초안과 원본 의견은 독립적이다. 작성자·피드백·원본 의견 ID는 복사하지 않는다. 채택안 원문은 편집 화면에서 대조하며, 제목·소개와 업체 전달용 요약을 편집한다. 공개 응답에는 원문을 포함하지 않는다.
- 저장과 편집은 로그인한 가족만 가능하다. 발행 전 공개 주소는 404이며, 퍼블리시하면 현재 편집 내용과 발행 상태를 함께 저장한다.
- `/share/[id]`는 로그인 없이 볼 수 있는 읽기 전용 페이지다. 추측하기 어려운 UUID 주소를 사용하고 검색 노출을 막는다. 발행 후 변경을 서버에서도 거부한다. 링크를 받은 사람은 누구나 열 수 있다.
- Vercel Private Blob의 별도 publications 경로에 저장한다. 비교 후 갱신으로 동시 저장·발행 충돌을 막고 요청 ID로 재시도를 처리한다. 원본이 변경되거나 재배포되어도 저장된 이미지는 바뀌지 않는다.
- OpenRouter 무료 모델로 중복을 합쳐 공사 방향·공통 요청·공간별 작업·업체 확인 사항을 생성한다. 모든 채택안의 근거 ID가 반영되었는지 검사하고, 충돌·미확정 사항은 임의로 결정하지 않도록 지시한다. 최종 내용은 사람이 편집하고 발행한다.
- AI 호출은 로그인 후에만 가능하며 서버에 저장된 초안의 공간·본문만 전송한다. 무료 모델과 입출력 단가 0 제한을 함께 사용한다. 실패 시 기존 편집을 보존하고 직접 작성을 지원한다. 키는 서버 전용 환경변수로 관리한다.
